# prefixgate

The prefixgate dashboard on a free CPU Space (2 vCPU, 16 GB). Source, method and results:
[github.com/Sebastianrodaaa/prefixgate](https://github.com/Sebastianrodaaa/prefixgate).

- **agent tab (opens first): replays.** The 24 runs in `results/agent_runs.json` are replays of a real, recorded CPU
  run: Llama 3.2 3B Instruct (`unsloth/Llama-3.2-3B-Instruct@006f5dc`, fp32, greedy, 8 threads) wrote each tool call
  and the trained Qwen2.5-0.5B gate scored every prefix. Nothing on this page is generated by Llama now.
- **Live agent is off here.** Llama 3.2 3B needs about 15 GB of RAM in fp32 next to the gate, and on 2 CPU threads
  a single call took 36 s (`git-status` and `rm-rf-home`, 2 threads pinned to 2 cores) instead of the 11 to 28 s
  it takes on 8. Llama 3.2 1B was faster (20 to 22 s) but wrote the wrong tools, e.g. a Stripe transfer for
  `rm -rf`. Run the live agent locally with `make demo`.
- **live tab: real.** Paste a tool call and the trained Qwen2.5-0.5B gate scores it token by token here, in about
  1 to 2.5 s on 2 CPUs.
- **replay tab: real.** The 776 held-out Policy Gates calls from the committed run.

Nothing is executed: allow, deny and escalate only change what the page shows.
